# ميزان — Domain Discovery
## الخطوة 3: Entities و Value Objects (نطاق MVP 0)

---

## الفرق بينهم

| | Entity | Value Object |
|---|---|---|
| **يتعرّف بـ** | هوية (Id) | قيمته فقط |
| **إذا تغيرت بياناته** | يبقى نفس الشيء | يصير شيء ثاني |
| **قابل للتعديل؟** | نعم | لا (Immutable) — تنشئ واحد جديد بدله |
| **مثال** | المصروف: لو عدّلت مبلغه يبقى نفس المصروف | 50 ريال: ما يهمك "أي" 50 ريال |
| **يحمي قواعده** | نعم، عبر دواله | نعم، **عند الإنشاء**: ما ينوجد Value Object غير صالح |

**القاعدة الذهبية:** إذا سألت "هل هذا نفس الشيء؟" والجواب يعتمد على Id → Entity. إذا يعتمد على القيم → Value Object.

**ليش Value Objects مهمة؟** بدل ما يكون المبلغ `decimal` عادي ممكن يكون سالب أو بعملة غلط في أي مكان بالكود، يكون `Money` يتحقق من نفسه مرة وحدة. كل مكان يستلم `Money` يثق فيه بدون ما يعيد التحقق.

## ثلاث قرارات تصميم مهمة (اقرأها بتمعن)

### القرار 1: فصل Category عن BudgetAllocation

الطريقة البديهية: كل ميزانية فيها فئات خاصة فيها. لكن عندها، المصروف يشير لفئة في ميزانية **فترة معينة**. لو المستخدم غيّر تاريخ المصروف لفترة ثانية، لازم نبحث عن "نفس الفئة" في الميزانية الثانية بالاسم، وهذا هش.

**الحل:** الفئة (Category) شيء دائم على مستوى المستخدم، والميزانية تحمل فقط **حد** كل فئة لفترتها (Allocation). المصروف يشير للفئة الدائمة، والفترة تُستنتج من تاريخه (BR-P7). نسخ الميزانية للفترة الجديدة (D2) يصير مجرد نسخ الحدود.

### القرار 2: الأشياء المحسوبة ما تُخزَّن

"المصروف" و"المتبقي" و"النسبة" (BR-B6–B8) **ما تُخزَّن** في Budget، تُحسب من المصروفات وقت الطلب. لو خزّناها، لازم نضمن إنها تتحدث مع كل إضافة وتعديل وحذف وتغيير تاريخ، وأي خطأ يخلي الرقم المخزن يكذب. في MVP 0 الحساب سريع، فالأبسط والأصح نحسبها.

نفس الشيء لـ **المبلغ الحالي للهدف** = InitialAmount + مجموع المصروفات المرتبطة بالهدف. وحالة الهدف (مكتمل أو متأخر، BR-G8 و BR-G9) تُحسب كذلك.

### القرار 3: إضافة مبلغ للهدف = مصروف مرتبط بالهدف

قرار D4 يقول إن الإضافة للهدف تُحسب من فئة "الادخار". بدل ما نسجل "إضافة" في الهدف **و** "مصروف" في الميزانية (شيئين لازم يبقون متطابقين للأبد)، نسجل **شيء واحد**: Transaction في فئة Savings ومعه GoalId. كذا يكون عندنا **مصدر حقيقة واحد (Single Source of Truth)**، ومستحيل يختلف رقم الهدف عن رقم الميزانية.

## أشياء ليست Entities ولا Value Objects

| الشيء | ليش | وش هو |
|---|---|---|
| **Insights** (الانحراف، التوقع) | ما لها هوية ولا تُخزَّن، تُحسب كل مرة من البيانات | **Domain Services** أو حسابات (BR-N1–N5) |
| **Dashboard** | تجميع لعرض بيانات من أكثر من مكان | **Read Model** في طبقة الـ Application |
